# 企业微信预约填报通知系统

自动监控客户经理次日预约填报情况，按时向企业微信发送提醒和通报。

---

## 通知时间表

除周通报外，所有通知**仅周一至周五发送**（周末不产生预约）。共 24 个定时任务：22 个受工作日限制，2 个为周通报。

| 通知类型 | 发送时间 | 发送对象 | 触发条件 |
|---|---|---|---|
| 客户经理个人提醒 | 18:00 / 18:45 / 19:15 / 19:45 / 20:15 / 21:00 / 22:00 / 23:00 | 各客户经理（个人） | 未达 2 户才发，达标跳过 |
| 简洁通报（张端） | 18:30 / 19:00 / 19:30 / 20:00 / 20:30 / 21:00 / 21:30 | 张端副经理 | 仍有人未填时发送 |
| 简洁通报（钟俊杰） | 19:00 / 19:30 / 20:30 / 21:00 / 21:30 | 钟俊杰经理 | 仍有人未填时发送 |
| 详细通报 | 22:00 | 全体管理者 | 工作日固定发送 |
| 最终数据收集 | 23:30 | —（不发消息） | 判定填报状态，写入统计表 |
| 周通报 | 周三 12:15 / 周日 12:00 | 全体客户经理 + 管理者（14 人） | 固定发送，**不受工作日限制** |

每次通知发送前自动从金山文档同步最新数据；同一时段多个任务共用一次同步，5 分钟内不重复拉取。

---

## 目标日期与考核窗口

通报针对的是「下一个工作日」的预约，周五顺延到下周一：

| 发送日 | 目标日期 | 考核窗口 | 消息措辞 |
|---|---|---|---|
| 周一 ~ 周四 | 次日 | 目标日当天 | 明日 |
| 周五 | 下周一 | **周六 ~ 周一，三天合计** | 周末至下周一 |

周五按三天窗口计数，是因为部分客户经理周末也上班、可能在周末安排走访。只要周六、周日、周一加起来够 2 户即算达标，周五的提醒里日期行会显示为 `📅 日期：2026-08-08 ~ 2026-08-10（三天合计）`。

日期逻辑集中在 `reporter.py` 的 `next_workday()` / `target_window()` / `records_in_window()`，`scheduler.py` 与 `api.py` 都调用同一份实现。

### 群内 @ 机制

企业微信群机器人只支持两种 @ 方式，`sender.py` 中 `wecom_userid` 优先，为空时回退到 `mobile`：

| 字段 | 对应载荷 | 说明 |
|---|---|---|
| `wecom_userid` | `mentioned_list` | 企业微信管理后台 → 通讯录 → 成员详情中的账号，最稳定 |
| `mobile` | `mentioned_mobile_list` | 需与成员企业微信绑定手机号一致，换号或未绑定会静默失效 |

config.py 中 15 人（12 客户经理 + 3 管理者）均已配置手机号，当前全部可被 @。消息正文里写的 `@麦海芬` 只是普通文字，不会高亮也不会触发提醒 —— 真正让手机响的是同一请求中的 `mentioned_mobile_list`。

## 通报示例

### 1. 客户经理个人提醒（发给本人）

```
📋 @麦海芬

明日预约填报提醒（第2次）
📅 日期：2026-08-04
✅ 已填：1 户
⚠️ 还需：1 户

📊 本月记录：
   ⏱️ 超时填报：3 次
   ❌ 漏填：1 次

💡 温馨提示：请尽快完成填报，确保明日工作顺利开展~
```

开启下午茶基金提醒后，末尾追加：

```
☕ 下午茶基金提醒：
   · 本月漏填 1 次（× 10 元/次）= 10 元
   请上交 10 元至部门下午茶基金。
```

> 已填报 ≥ 2 户时本条消息不发送。"本月记录"仅在有超时或漏填时显示。

## 填报状态说明

| 状态 | 判定条件 |
|---|---|
| 准时（on_time） | 23:30 前已填 ≥ 2 户，且最后一条记录上传时间 ≤ 19:30 |
| 超时（overtime） | 23:30 前已填 ≥ 2 户，但最后一条记录上传时间 > 19:30 |
| 漏填（missing） | 23:30 时仍未达到 2 户 |

## 下午茶基金（可选）

在前端「系统」Tab 的「☕ 下午茶基金提醒」开关开启后，客户经理个人提醒中自动附加罚款计算：

| 触发条件 | 金额 |
|---|---|
| 本月漏填 N 次 | N × 10 元 |
| 本月超时填报累计满 5 次 | 每满 5 次 10 元 |

两项合计为 0 时不显示该提醒块。

## 快速开始

```bash
# 安装依赖
pip install APScheduler>=3.10.0

# Webhook 已内置端州政企群地址（config.py 的 DEFAULT_WEBHOOK_URL），无需配置。
# 要发到其他群时才需覆盖：
# WECOM_NOTICE_WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY

# 启动服务
python wecom_notice/main.py
# 服务运行在 http://127.0.0.1:8996
```

启动后在前端「系统」Tab 手动开启调度器，或调用：
```bash
curl -X POST http://127.0.0.1:8996/api/scheduler/start
```

## 运行日志

前端「运行日志」Tab 展示每次消息发送的结果，数据来自 `send_logs` 表：时间、规则、状态、接收人、消息摘要、错误。表格中长内容会截断，**点击任意一行**可弹窗查看完整消息正文和错误堆栈。

## 历史记录清零

需要设定「从某天开始计算，之前的漏填/超时一律免除」时，用 `reset_history.py`，把该日期之前的 `overtime` / `missing` 记录改为 `on_time`：

```bash
# 预览（默认 dry-run，只打印将影响的记录）
python -m wecom_notice.reset_history --before 2026-08-04 --archive-visits

# 确认后执行，会先自动备份数据库到 runtime/backup/
python -m wecom_notice.reset_history --before 2026-08-04 --archive-visits --apply
```

| 参数 | 说明 |
|---|---|
| `--before` | 起算日，**不含**当天。`--before 2026-08-04` 会保留 08-04 的记录。默认今天 |
| `--apply` | 真正写入；不加则只预览 |
| `--archive-visits` | 同时归档起算日前的 `visit_records` |

`--archive-visits` 建议一并使用：`fill_statistics` 为空时部分汇总会从 `visit_records` 反推历史漏填，只清 `fill_statistics` 的话记录可能重新长回来。

执行前先停掉调度器，避免与 23:30 的最终数据收集任务撞上。
